## 표현과 정보 범위

특정 조직의 역할과 비공개 환경을 전제로 한 설명을 일반적인 입력·출력 계약으로 바꿨다.
컴퓨존 상품명 분석이라는 목적은 유지하고 독립 개발 프로젝트임을 명시했다.
공개 응답의 계약 설명도 특정 조직명 대신 `host application`으로 바꿨다.
매칭·검증 알고리즘은 변경하지 않았다.

예를 들어 “기본 오프라인 결과는 검증 근거가 없으면 needs_review다”라는 문장은
“기본 실행은 오프라인이므로 독립적인 페이지 근거가 없으면 보류한다”로 풀었다.
긴 문단은 문장마다 줄을 나누고 주제가 바뀌는 곳에서 문단을 구분했다.
기술 문서의 필드·상태 값, CSV 호환 열 이름, 코드와 URL은 보존했다.

## 구현과 대조한 내용

공개 상품명 예시 세 개를 실행해 모델·유통사·후속모델 분리를 확인했다.
GPU의 일반 드라이버 요청과 보드 펌웨어 요청은 제공사 판단을 구분한다.
NVIDIA App 예시의 기본 오프라인 결과는 `needs_review`다.
검증하지 않은 실제 페이지를 성공한 예시로 쓰지 않았다.

영상의 URL은 실제 GIGABYTE 공식 페이지로 바꿨다.
공개 검색 후보 5개를 실제 Skill wrapper로 온라인 실행한 원문 응답을 보존했다.
사이트의 브라우저 확인 요구로 `needs_review`, `approved=false`, `candidates=[]`가 반환됐다.
표의 검색 후보 5개를 검증 통과 목록으로 설명하지 않는다.
직접 입력·저장은 연결 프로그램의 화면 재현이며 실제 저장은 수행하지 않는다.

## 공개 이력 검사

공개 main·태그와 닫힌 PR 2개의 참조에서 도달 가능한 커밋 9개를 확인했다.
Release 1개와 첨부파일 6개를 포함해 751개 파일·본문을 알려진 비밀 패턴과 비공개 경로 기준으로 검사했다.
해당 패턴은 검출되지 않았다.
과거 이력과 Release 자산에는 개편 전 조직 설명이 남아 있다.

이 검사는 모든 민감정보의 부재를 보장하지 않는다.
삭제되거나 도달할 수 없는 객체와 제삼자의 복사본은 검사 범위에 포함하지 않는다.
과거 커밋·태그와 기존 Release 자산은 수정하지 않았다.

## 검증 방법

`npm test`, `npm run lint`, `npm run validate`로 기존 동작과 공개 파일을 검사한다.
README 미리보기는 파일 형식·크기를 제한하고 패키지에 함께 포함되는지 확인한다.
Markdown의 상대 링크·코드 블록·표·Mermaid와 이미지 표시를 별도로 검증한다.
영상은 HyperFrames의 런타임·레이아웃·대비 검사, 전체 MP4 디코딩과 추출 프레임 확인을 수행한다.
실제 유료 검색·Luna 비교와 외부 서비스 게시를 실행한 결과로 해석해서는 안 된다.

# 모델 지원과 SW 배포 근거

페이지가 열린다는 것과 해당 제품을 지원한다는 것은 다른 확인 항목이다.
매처는 접속 상태, 모델 지원, SW 실행·다운로드 대상을 `verification`에 나눠 기록한다.
모델 이름이 한 번 등장하거나 공식 도메인이라는 이유만으로 후보를 통과시키지 않는다.

## 무엇을 확인하나

모델별 페이지에서는 정확 모델의 지원 문맥과 맞는 SW 링크를 확인한다.
미지원·제외 안내, 다른 모델용 파일, 리비전 충돌이 있으면 보류한다.
일반 키보드·마우스 요청에는 펌웨어만 있는 페이지를 대신 넣지 않는다.
펌웨어가 필요하면 `requested_software_kind: "firmware"`로 요청한다.

공통 앱은 공식 FAQ나 매뉴얼의 지원 범위와 배포 허브를 연결한다.
최종 허브에 모든 모델명이 없더라도 같은 SW의 지원 관계와 다운로드 제어가 확인되면 후보가 될 수 있다.
웹 설정 도구는 설치 파일 대신 실제 연결·설정 제어를 확인한다.
여기서 장치 연결이나 설치까지 실행하는 것은 아니다.

접속 차단, 빈 자료실, 검색 실패, JavaScript로만 표시되는 정보는 SW 없음의 증거가 아니다.
실행 시 확인한 근거는 `support_evidence`에 출처와 함께 남긴다.
과거 매핑만 읽은 결과는 `registry_recheck_required`이며 실접속 날짜를 만들지 않는다.

## 공개 근거 데이터

기존 vendor의 `models`와 `ecosystems`에 `evidence`를 추가한다.
별도 정답 데이터베이스를 만들거나 검수 CSV를 공개 Registry로 복사하지 않는다.

관계 유형은 `software-support`, `driver-support`, `common-manual`, `regional-name`,
`configuration-profile`, `official-distribution`, `software-absence`로 구분한다.
각 근거에는 출처 URL, 관찰 내용, 확인일, 모델, SW 종류, 적용 범위와 미확인 사항을 적는다.
`canonical_page`는 고객에게 보여줄 주소이고 `source_url`은 검증 근거다.
실행 도구가 별도라면 `launch_url`로 구분한다.

공통 설명서와 구성 프로필은 그 자체로 드라이버·펌웨어 호환을 확정하지 않는다.
새 관계가 포함된 공개 데이터는 기존 검증기에서 거부될 수 있다.
엔진과 스키마를 함께 갱신해야 한다.

## 한국어와 지역 예외

지원 범위와 유효성 검사를 통과한 후보끼리는 HTML 언어와 한국어 선택 제어를 확인해 정렬한다.
`kr.msi.com`, `/kr/ko/`, `/ko-kr/`, `ko_KR` 같은 URL 표기는 지역 힌트다.
그 모양만으로 한국어 지원을 확정하지 않는다.
Luna의 순위도 이 정책 안에서만 적용한다.

Canon처럼 해외 페이지를 쓰는 경우에는 `locale.exception_reason`에 이유를 남긴다.
`locale.page_language`와 `locale.software_languages`는 각각 페이지 언어와 지원 문서에서 확인한 프로그램 언어다.

## 세트상품과 검증 범위

구성품은 최대 4개까지 자동 조사하고, 결과를 `component_results`에 보존한다.
SW 대상이 하나이며 나머지 구성품의 SW 없음이 해당 요청 범위에서 명시적으로 확인된 경우만 그 대상을 선택한다.
복수 대상이나 미확인 구성품이 있으면 상위 후보를 비워 두고 수동 선택을 기다린다.
`target_component`로 지정하면 해당 구성품만 처리한다.

명시적 없음 근거도 모델·요청 종류·확인일이 맞고 유효기간 안에 있어야 한다.
CPU라는 분류나 파일 검색 실패만으로 없음 규칙을 만들지 않는다.
테스트의 CPU 없음 조건은 합성 데이터이며 실제 Intel 제품에 관한 판정이 아니다.

온라인 처리는 요청 전체 30초, 후보 페이지 최대 5개와 근거 페이지 최대 8개가 기본 상한이다.
같은 페이지는 재사용하고 순차 요청 사이의 간격을 적용한다.
세트상품도 전체 요청의 한도를 공유한다.
각 응답은 최대 1 MiB이고 리다이렉트의 공식 호스트와 공인 IP를 확인한다.

합성 반례 테스트, 공개 페이지 실접속, Skill 지침을 적용한 사례 검토는 서로 다른 검증이다.
어느 하나의 통과율을 전체 추천 정확도나 실제 모델 성능으로 설명하지 않는다.
